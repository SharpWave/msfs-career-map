# Start Lists — EARS Specs

Design: [start-lists-design.md](start-lists-design.md), with the shared items
[desktop-design.md](../desktop-design.md) assigns to it. Prefix `DESK-START`; facets `MSFS` (Start with
MSFS: the editions and their folders, the tray item's tick, words, clicks and what its reads log, the
app's entry and an earlier program path, the `EXE.xml` editor's steps for turning it on and off, its
backups, files left as they were, an entry another program removed), `WINDOWS` (Start with Windows: the
Run and StartupApproved values, their backup, the tray item), `UNREG` (`--unregister`: what it removes,
the record of files last written it clears, its log, its exit codes, its 15 s bound and its start in test
mode), `TEST` (test mode leaving both start lists alone, and the start lists' unit tests).

"Outside test mode" (no `--test-data=<folder>`) is the installed app: only the installed program runs
outside test mode (DESK-DIST-DEV-004). A copy run from source with npm (`npm run dev`, `npm start`) runs
no desktop shell, and the unpackaged desktop shell (`npm run desktop`) runs only in test mode, so neither
reaches a start list.

`[x]` implemented · `[ ]` intended, not yet implemented · `[D]` deferred

## Starting with MSFS

- [ ] **DESK-START-MSFS-001**: The desktop shell shall offer **Start with MSFS 2024** in the tray menu of a copy not in test mode, off until the pilot turns it on, and shall add the app's entry to an `EXE.xml` only when the pilot turns it on there.
- [ ] **DESK-START-MSFS-002**: The desktop shell shall look for each MSFS 2024 edition's `UserCfg.opt` and `EXE.xml` in that edition's one folder: `%LOCALAPPDATA%\Packages\Microsoft.Limitless_8wekyb3d8bbwe\LocalCache` for the Microsoft Store / Xbox edition and `%APPDATA%\Microsoft Flight Simulator 2024` for the Steam edition.
- [ ] **DESK-START-MSFS-003**: The desktop shell shall count an MSFS 2024 edition as installed only while its folder (DESK-START-MSFS-002) holds `UserCfg.opt`, and shall count an `EXE.xml` as present whenever one exists in either edition's folder, whether or not that edition is still installed.
- [ ] **DESK-START-MSFS-004**: The desktop shell shall judge MSFS 2024 running while a process named `FlightSimulator2024.exe` runs for this Windows account, whichever edition it belongs to.
- [ ] **DESK-START-MSFS-005**: The desktop shell shall count an entry of the app's in `EXE.xml` (DESK-START-MSFS-022) as turned on only when its `Disabled` and `ManualLoad` values are both False — each trimmed of surrounding whitespace and compared without regard to case — and as turned off otherwise.
- [ ] **DESK-START-MSFS-006**: While the tray menu offers Start with MSFS 2024 (outside test mode, no `--test-data=<folder>`), it shall show the item ticked when, and only when, an `EXE.xml` present (one in either MSFS 2024 edition's folder, its edition installed or not) holds an entry of the app's turned on (`Disabled` and `ManualLoad` both False).
- [ ] **DESK-START-MSFS-007**: When the pilot turns Start with MSFS 2024 on, the desktop shell shall write the app's entry, by the steps of DESK-START-MSFS-025 to DESK-START-MSFS-043, to the `EXE.xml` of every MSFS 2024 edition installed (its folder holding `UserCfg.opt`) unless that file already holds exactly one entry of the app's, turned on and the same as the app's entry (DESK-START-MSFS-028), and to no `EXE.xml` of an edition not installed.
- [ ] **DESK-START-MSFS-008**: When the pilot turns Start with MSFS 2024 off, the desktop shell shall remove the app's entries, by the steps of DESK-START-MSFS-044 to DESK-START-MSFS-048, from every `EXE.xml` present that has one — in either MSFS 2024 edition's folder, whether or not that edition is still installed — so an entry the app wrote is still removed after its edition is uninstalled and its folder left behind.
- [ ] **DESK-START-MSFS-009**: When MSFS 2024 quits, the desktop shell shall keep running in the tray, a copy that MSFS started through `EXE.xml` (`--background`) included.
- [D] **DESK-START-MSFS-010**: Where MSFS 2020 is installed, the desktop shell shall also offer to start the app with MSFS 2020, adding the app's entry to MSFS 2020's own `EXE.xml` only when the pilot asks and removing it from there, as Start with MSFS 2024 does for MSFS 2024's `EXE.xml`.

## Starting with MSFS: The Item

- [ ] **DESK-START-MSFS-011**: When the tray menu opens in a copy outside test mode (no `--test-data=<folder>`), the desktop shell shall read the Start with MSFS 2024 item's state — the MSFS 2024 editions installed, the `EXE.xml` files present and the app's entries in them, and whether MSFS 2024 is running for this Windows account (`FlightSimulator2024.exe`, DESK-START-MSFS-004) — and show the item's tick and words from it.
- [ ] **DESK-START-MSFS-012**: When the pilot clicks Start with MSFS 2024 while the desktop shell is not quitting (DESK-SHELL-QUIT-003: while quitting, every tray item but Open MSFS Career Map and Show log is ignored), the desktop shell shall read the item's state (DESK-START-MSFS-011) again and act on that fresh state rather than the state read as the menu opened, turning the setting off when the fresh state is ticked and on when it is unticked (unless MSFS 2024 is running, DESK-START-MSFS-020).
- [ ] **DESK-START-MSFS-013**: While the tray menu offers Start with MSFS 2024 (outside test mode, no `--test-data=<folder>`), it shall word the item by the first of DESK-START-MSFS-014 to DESK-START-MSFS-019 that applies to its state, its tick showing as DESK-START-MSFS-006 says.
- [ ] **DESK-START-MSFS-014**: While the tray menu offers Start with MSFS 2024 (outside test mode, no `--test-data=<folder>`), the item is unticked and neither MSFS 2024 edition is installed (no `UserCfg.opt` in either edition's folder), the tray menu shall show the item unclickable, as "Start with MSFS 2024 (MSFS 2024 not found)".
- [ ] **DESK-START-MSFS-015**: While the tray menu offers Start with MSFS 2024 (outside test mode, no `--test-data=<folder>`) and MSFS 2024 is running for this Windows account (`FlightSimulator2024.exe`, DESK-START-MSFS-004), the tray menu shall show the item unclickable, ticked or not, as "Start with MSFS 2024 (close MSFS to change)", unless DESK-START-MSFS-014 applies.
- [ ] **DESK-START-MSFS-016**: While the tray menu offers Start with MSFS 2024 (outside test mode, no `--test-data=<folder>`), the item is unticked and an `EXE.xml` present cannot be read — it cannot be opened, does not parse as XML, has a root other than `SimBase.Document` with `Type="Launch"`, or is in an encoding other than UTF-8 and windows-1252; one empty or holding only whitespace counts as read — the tray menu shall show the item, clickable, as "Start with MSFS 2024 (EXE.xml can't be read; see log)", the file and why being in `desktop.log` (written once each time that file becomes unreadable, DESK-START-MSFS-055), unless DESK-START-MSFS-014 or DESK-START-MSFS-015 applies.
- [ ] **DESK-START-MSFS-017**: While the tray menu offers Start with MSFS 2024 (outside test mode, no `--test-data=<folder>`), the item is unticked and an `EXE.xml` that the desktop shell's settings record as last written with the app's entry (DESK-START-MSFS-052) no longer holds an entry of the app's, the tray menu shall show the item, clickable, as "Start with MSFS 2024 (removed by another program; click to add again)" until the pilot clicks it (the click bringing that record up to date, DESK-START-MSFS-052), unless one of DESK-START-MSFS-014 to DESK-START-MSFS-016 applies.
- [ ] **DESK-START-MSFS-018**: While the tray menu offers Start with MSFS 2024 (outside test mode, no `--test-data=<folder>`), the item is unticked and an `EXE.xml` present holds an entry of the app's turned off (its `Disabled` or `ManualLoad` not False), the tray menu shall show the item, clickable, as "Start with MSFS 2024 (turned off in EXE.xml)", unless one of DESK-START-MSFS-014 to DESK-START-MSFS-017 applies.
- [ ] **DESK-START-MSFS-019**: While the tray menu offers Start with MSFS 2024 (outside test mode, no `--test-data=<folder>`) and none of DESK-START-MSFS-014 to DESK-START-MSFS-018 applies, the tray menu shall show the item, clickable, as "Start with MSFS 2024".
- [ ] **DESK-START-MSFS-020**: If MSFS 2024 is running for this Windows account (`FlightSimulator2024.exe`) when the state is read again at a click on Start with MSFS 2024, then the desktop shell shall write nothing — no `EXE.xml`, backup or settings record — and show a message box saying "Close MSFS to change Start with MSFS 2024."
- [ ] **DESK-START-MSFS-055**: When the desktop shell reads the Start with MSFS 2024 item's state outside test mode (no `--test-data=<folder>`) — as the tray menu opens or at a click (DESK-START-MSFS-011, DESK-START-MSFS-012) — and finds that an `EXE.xml` present cannot be read (it cannot be opened, does not parse as XML, has a root other than `SimBase.Document` with `Type="Launch"`, or is in an encoding other than UTF-8 and windows-1252; one empty or holding only whitespace counting as read), it shall write the file and why to `desktop.log` only when that state starts — at the first read since the desktop shell started that finds the file unreadable, or the first after a read that found it readable or absent — and not again at each later read that finds it unreadable.

## Starting with MSFS: The App's Entry

- [ ] **DESK-START-MSFS-021**: When the desktop shell writes the app's entry to an `EXE.xml`, it shall write a `Launch.Addon` element holding, in this order, `Name` "MSFS Career Map" (the start-list entries' name, which never changes), `Disabled` "False", `ManualLoad` "False", `Path` the installed program's full path written out expanded, never as an environment variable (`C:\Users\<user>\AppData\Local\Programs\MSFS Career Map\MSFS Career Map.exe`, the program `MSFS Career Map.exe`, DESK-DIST-PKG-003, in the install folder `%LOCALAPPDATA%\Programs\MSFS Career Map`, DESK-DIST-INST-009), XML-escaped, and `CommandLine` "--background", and nothing else.
- [ ] **DESK-START-MSFS-022**: The desktop shell shall treat an `EXE.xml` entry as the app's only when its `Name`, trimmed of surrounding whitespace, is "MSFS Career Map" compared without regard to case, and its `Path`, as parsed and XML-unescaped (`&amp;` read as `&`), is the installed program's full path (`C:\Users\<user>\AppData\Local\Programs\MSFS Career Map\MSFS Career Map.exe`, expanded) compared without regard to case, and shall treat every other entry — one naming the same program under another name included — as another program's, which it never changes or removes.
- [ ] **DESK-START-MSFS-023**: The desktop shell shall compare `EXE.xml` entries as parsed, never by their bytes, and count an entry of the app's as the same as the app's entry (DESK-START-MSFS-021) when it holds the five elements `Name`, `Disabled`, `ManualLoad`, `Path` and `CommandLine` and no others, in any order, each value trimmed of surrounding whitespace and equal to the app's entry's — `Path` compared as in DESK-START-MSFS-022, False and True without regard to case — and as altered otherwise.
- [ ] **DESK-START-MSFS-024**: The installed program shall never ask to run elevated, since MSFS does not start a program that does.
- [ ] **DESK-START-MSFS-054**: If a release changes the installed program's path (the program name and install folder never change from one release to the next, DESK-DIST-PKG-006, short of a change that cannot be avoided), then that release's desktop shell shall also treat an `EXE.xml` entry named "MSFS Career Map" whose `Path` is the earlier installed program's full path as the app's (DESK-START-MSFS-022).

## Starting with MSFS: Turning It On

- [ ] **DESK-START-MSFS-025**: When Start with MSFS 2024 is turned on and an MSFS 2024 edition installed has no `EXE.xml` in its folder, the desktop shell shall write a new one through its temporary file and rename (DESK-START-MSFS-038 to DESK-START-MSFS-042, the re-read before the rename expecting still no file): UTF-8 without a byte-order mark, an XML declaration, and a `SimBase.Document` root with `Type="Launch"` and `version="1,0"` holding `Descr` "Launch", `Filename` "EXE.xml", `Disabled` "False", `Launch.ManualLoad` "False" and the app's entry (DESK-START-MSFS-021).
- [ ] **DESK-START-MSFS-026**: When Start with MSFS 2024 is turned on and an edition installed's `EXE.xml` is empty or holds only whitespace, the desktop shell shall back it up (DESK-START-MSFS-029) and then replace it whole with a new file written as DESK-START-MSFS-025 says (UTF-8 without a byte-order mark), through its temporary file and rename (DESK-START-MSFS-038 to DESK-START-MSFS-042, the re-read before the rename expecting the bytes it first read).
- [ ] **DESK-START-MSFS-027**: If an existing `EXE.xml`, neither empty nor only whitespace, that the desktop shell takes up — an installed edition's when Start with MSFS 2024 is turned on, any present when it is turned off or at `--unregister` — does not parse with an XML parser, has a root other than `SimBase.Document` with `Type="Launch"`, is in an encoding other than UTF-8 or windows-1252, or cannot hold the installed program's path in its encoding (checked when removing the app's entries as well as when adding one), then the desktop shell shall leave that file untouched, whether or not an entry of the app's can be found in it, write why to `desktop.log`, and, when the pilot turned the setting on or off, name the file and why in the message box (DESK-START-MSFS-049), or, at `--unregister`, count it as an `EXE.xml` that could not be checked (DESK-START-UNREG-003).
- [ ] **DESK-START-MSFS-028**: When Start with MSFS 2024 is turned on and an edition installed's `EXE.xml` holds exactly one entry of the app's, turned on and the same as the app's entry (DESK-START-MSFS-023), the desktop shell shall write nothing for that file and take no backup of it.
- [ ] **DESK-START-MSFS-029**: When the desktop shell is about to change an existing `EXE.xml` — turning Start with MSFS 2024 on or off, or `--unregister` — it shall first copy it into the `start-up list backups` folder in Electron's own folder (`%APPDATA%\MSFS Career Map`) as `EXE.xml.<Store|Steam>.<yyyyMMddTHHmmssZ>`, named for the edition whose folder holds it and the UTC time to the second, ending in `Z`, adding `-2`, `-3`, … after the time when a backup of that edition already has that name.
- [ ] **DESK-START-MSFS-030**: When the desktop shell has copied an `EXE.xml` into the `start-up list backups` folder, it shall keep the five newest backups of that edition's `EXE.xml` there, newest judged by the UTC time in the name and then by its `-2`, `-3`, … suffix, never by the file's own times, and delete older ones, deleting only files named as its own `EXE.xml` backups (`EXE.xml.<Store|Steam>.<yyyyMMddTHHmmssZ>`, with or without a `-2`, `-3`, … after the time).
- [ ] **DESK-START-MSFS-031**: If the backup copy of an `EXE.xml` (DESK-START-MSFS-029) cannot be written, then the desktop shell shall change nothing in that file, and, when the pilot turned Start with MSFS 2024 on or off, the message box shall name the backup and the reason.
- [ ] **DESK-START-MSFS-032**: When Start with MSFS 2024 is turned on and an edition installed's existing `EXE.xml`, neither empty nor only whitespace, holds no entry of the app's, the desktop shell shall insert the app's entry as text, in the file's own encoding, just before the root's closing tag, indented like the file's other entries and with the file's line endings, or inline when the file's entries share one line.
- [ ] **DESK-START-MSFS-033**: When Start with MSFS 2024 is turned on and the first entry of the app's in an edition installed's `EXE.xml` is turned off or altered, the desktop shell shall rewrite that entry in place as the app's entry (DESK-START-MSFS-021) instead of inserting one.
- [ ] **DESK-START-MSFS-034**: When Start with MSFS 2024 is turned on and an edition installed's `EXE.xml` holds more than one entry of the app's, the desktop shell shall keep the first, as DESK-START-MSFS-033 leaves it, and remove the others as turning it off removes an entry (DESK-START-MSFS-045).
- [ ] **DESK-START-MSFS-035**: When Start with MSFS 2024 is turned on and an edition installed's `EXE.xml` has a self-closing root, the desktop shell shall rewrite the root as an opening and a closing tag around the app's entry.
- [ ] **DESK-START-MSFS-036**: When the desktop shell changes an existing `EXE.xml` that is neither empty nor only whitespace — turning Start with MSFS 2024 on or off, or `--unregister` — it shall leave every byte as it was except the app's entries it inserts, rewrites or removes (with the lines DESK-START-MSFS-045 removes with them) and a self-closing root it opens, the byte-order mark included or left out as found.
- [ ] **DESK-START-MSFS-037**: When Start with MSFS 2024 is turned on and the desktop shell changes an installed edition's existing `EXE.xml` that is neither empty nor only whitespace, it shall parse the result before writing it, and unless the result holds every other child of the root — elements, comments and any text but the whitespace between them — unchanged and in the same order, the app's entry exactly once and turned on, and the root unchanged but for a self-closing tag opened, it shall write nothing to that file and name the file and why in the message box (DESK-START-MSFS-049).
- [ ] **DESK-START-MSFS-038**: When the desktop shell writes an `EXE.xml` — a new one where there is none (DESK-START-MSFS-025), a new one replacing a file empty or holding only whitespace (DESK-START-MSFS-026), or any other existing one changed by turning Start with MSFS 2024 on or off or by `--unregister` — it shall write the result to `EXE.xml.msfs-career-map-tmp` in the same folder and then rename that file to `EXE.xml`, over the file there if there is one.
- [ ] **DESK-START-MSFS-039**: When the desktop shell is about to rename its temporary file to `EXE.xml` (DESK-START-MSFS-038), it shall, just before the rename, look at `EXE.xml` again and compare it with what that file's change began from — no file, or the bytes it read when the change began (an empty or whitespace-only file, DESK-START-MSFS-026; any other, DESK-START-MSFS-027); when they differ — a file created where there was none, or the file changed, emptied or gone — it shall start that file's change again from its first step, taking a fresh backup (DESK-START-MSFS-029) of a file then there.
- [ ] **DESK-START-MSFS-040**: If the re-read before the rename (DESK-START-MSFS-039) has found `EXE.xml` different from what the change began from three times in one change of that file — a new file, a replaced empty one or a changed existing one — then the desktop shell shall write nothing to it and, when the pilot turned Start with MSFS 2024 on or off, say in the message box that another program is changing the file.
- [ ] **DESK-START-MSFS-041**: While Windows reports `EXE.xml` busy or access denied as the desktop shell renames its temporary file to `EXE.xml` (DESK-START-MSFS-038) — writing a new file, replacing an empty or whitespace-only one, or changing any other existing one — the desktop shell shall retry the rename every 250 ms for up to 3 s.
- [ ] **DESK-START-MSFS-042**: If renaming its temporary file to `EXE.xml` (DESK-START-MSFS-038) still fails after the retries (DESK-START-MSFS-041), then the desktop shell shall delete the temporary file, leave `EXE.xml` as it was — no file where there was none — and name the Windows error, in the message box when the pilot turned Start with MSFS 2024 on or off.
- [ ] **DESK-START-MSFS-043**: When the desktop shell takes up the MSFS 2024 editions' folders (DESK-START-MSFS-002) — turning Start with MSFS 2024 on or off once MSFS 2024 is found not running (DESK-START-MSFS-020), or `--unregister` outside test mode (no `--test-data=<folder>`) — it shall first delete its own temporary file `EXE.xml.msfs-career-map-tmp` (left by a change cut short, by a crash or a Windows session end) from each of those folders that holds one, whether or not that folder's `EXE.xml` then needs a change.

## Starting with MSFS: Turning It Off

- [ ] **DESK-START-MSFS-044**: When Start with MSFS 2024 is turned off, the desktop shell shall remove every entry of the app's from each `EXE.xml` present, turned on or not, and nothing else, through the checks and steps it shares with turning it on (DESK-START-MSFS-027, DESK-START-MSFS-029 to DESK-START-MSFS-031, DESK-START-MSFS-036 and DESK-START-MSFS-038 to DESK-START-MSFS-043).
- [ ] **DESK-START-MSFS-045**: When the desktop shell removes an entry of the app's from an `EXE.xml` — turning Start with MSFS 2024 off, turning it on (an entry beyond the first), or `--unregister` — it shall remove an entry whose lines hold nothing but it and whitespace together with those lines, and any other entry only by its own bytes.
- [ ] **DESK-START-MSFS-046**: When Start with MSFS 2024 is turned off and an `EXE.xml` present is empty or holds only whitespace, or passes the checks of DESK-START-MSFS-027 and holds no entry of the app's, the desktop shell shall write nothing for that file and take no backup of it (a file those checks refuse being left as it was and reported, DESK-START-MSFS-027, whether or not it holds an entry of the app's); where an edition's folder holds no `EXE.xml`, it shall create none.
- [ ] **DESK-START-MSFS-047**: The desktop shell shall never delete an `EXE.xml`, even when removing the app's entry leaves no entry in it.
- [ ] **DESK-START-MSFS-048**: When Start with MSFS 2024 is turned off or `--unregister` runs and the desktop shell changes an existing `EXE.xml` that is neither empty nor only whitespace, it shall parse the result before writing it, and unless the result holds every other child of the root — elements, comments and any text but the whitespace between them — unchanged and in the same order and no entry of the app's, it shall write nothing to that file and, when the pilot turned the setting off, name the file and why in the message box (DESK-START-MSFS-049).

## Starting with MSFS: Files Left as They Were

- [ ] **DESK-START-MSFS-049**: When the pilot turns Start with MSFS 2024 on or off and an `EXE.xml` cannot be changed, the desktop shell shall still change the others, and show one message box naming each file left as it was and why; the item, read again (DESK-START-MSFS-011), then shows the files as they are.
- [ ] **DESK-START-MSFS-050**: The desktop shell shall change nothing in either MSFS 2024 edition's folder but its `EXE.xml`, and that only as DESK-START-MSFS-036 allows (the app's entries inserted, rewritten or removed, a self-closing root opened) or by writing a new `EXE.xml` holding the app's entry (DESK-START-MSFS-025, DESK-START-MSFS-026), keeping its temporary file `EXE.xml.msfs-career-map-tmp` there only while writing (deleting one a change cut short left, by a crash or a Windows session end, DESK-START-MSFS-043) and never placing a backup there.

## Starting with MSFS: An Entry Another Program Removed

- [ ] **DESK-START-MSFS-051**: The desktop shell shall never put the app's entry back into an `EXE.xml` from which another program removed it, writing it there again only when the pilot turns Start with MSFS 2024 on.
- [ ] **DESK-START-MSFS-052**: When Start with MSFS 2024 is turned on or off, the desktop shell shall bring up to date the record in its settings of the `EXE.xml` files it last wrote the app's entry to, in an order a change cut short cannot turn into an entry read as removed by another program (DESK-START-MSFS-017): turning it on, adding each file to the record once that file's write has succeeded, or at once when it already held the app's entry as written (DESK-START-MSFS-028), and leaving in the record, once the change is done, only the files holding an entry of the app's turned on; turning it off, taking each file out of the record before removing that file's entry, and leaving the record empty once the change is done.
- [ ] **DESK-START-MSFS-053**: When the desktop shell reads the Start with MSFS 2024 item's state outside test mode (no `--test-data=<folder>`) — as the tray menu opens or at a click (DESK-START-MSFS-011, DESK-START-MSFS-012) — and finds that an `EXE.xml` its settings record as last written with the app's entry (DESK-START-MSFS-052) no longer holds an entry of the app's, it shall write that to `desktop.log` only when that state starts — at the first read since the desktop shell started that finds that file without the entry, or the first after a read that found it holding the entry or not in the record — and not again at each later read that finds it the same.

## Starting with Windows

- [ ] **DESK-START-WINDOWS-001**: The desktop shell shall offer **Start with Windows** in the tray menu of a copy not in test mode, off until the pilot turns it on, and shall write the app's value to Windows' start-up keys only when the pilot turns it on there.
- [ ] **DESK-START-WINDOWS-002**: When the desktop shell is about to change Windows' start-up keys — turning Start with Windows on or off, or `--unregister`, whenever that will change either key (DESK-START-WINDOWS-009) — it shall first export the values of both `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` and `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run` as one `.reg` file named `Run.<yyyyMMddTHHmmssZ>.reg` for the UTC time to the second, ending in `Z` (adding `-2`, `-3`, … before `.reg` when an export already has that name), into the `start-up list backups` folder in Electron's own folder (`%APPDATA%\MSFS Career Map`), keeping the five newest such exports, newest judged by the UTC time in the name and then by its suffix, never by the file's own times, and deleting older ones only among files named as its own exports.
- [ ] **DESK-START-WINDOWS-003**: If the `.reg` export of Windows' start-up keys (DESK-START-WINDOWS-002) cannot be written, then the desktop shell shall change neither key, and, when the pilot turned Start with Windows on or off, the message box shall name the backup and the reason.
- [ ] **DESK-START-WINDOWS-004**: When the tray menu opens in a copy outside test mode (no `--test-data=<folder>`), the desktop shell shall read Start with Windows' state — the value named "MSFS Career Map" under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, whatever it holds, and its mark under `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run` — and show the item from it.
- [ ] **DESK-START-WINDOWS-005**: When the pilot clicks Start with Windows while the desktop shell is not quitting (DESK-SHELL-QUIT-003: while quitting, every tray item but Open MSFS Career Map and Show log is ignored), the desktop shell shall read its state (DESK-START-WINDOWS-004) again and act on that fresh state rather than the state read as the menu opened, turning the setting off when the fresh state is ticked and on when it is unticked.
- [ ] **DESK-START-WINDOWS-006**: When Start with Windows is turned on, the desktop shell shall write, through Electron's login item, the value under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` named explicitly "MSFS Career Map" (the start-list entries' name, which never changes, not the name Electron would take from the AppUserModelID) holding the installed program's path in quotes followed by `--background`, and mark that value enabled under `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run`, so the tick overrides an earlier Disable in Task Manager's Startup apps.
- [ ] **DESK-START-WINDOWS-007**: While the tray menu offers Start with Windows (outside test mode, no `--test-data=<folder>`), it shall show the item ticked when, and only when, Windows will start the app at sign-in — `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` holds a value named "MSFS Career Map", whatever program it holds (the app's value), and `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run` does not mark it disabled — so turning the app off in Task Manager's Startup apps unticks it.
- [ ] **DESK-START-WINDOWS-008**: When Start with Windows is turned off, the desktop shell shall remove the value named "MSFS Career Map" — the app's, whatever it holds — from both `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` and `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run`, and change nothing else in either key.
