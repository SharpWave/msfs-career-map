# Desktop Shell — EARS Specs

Design: [shell-design.md](shell-design.md), with the shared items [desktop-design.md](../desktop-design.md)
assigns to it. Prefix `DESK-SHELL`; facets `SRV` (the server's process: starting it, readiness, talking
to it, shutting it down, keeping it running, sleep and the clock), `QUIT` (the quitting state), `BAK`
(when backups are asked for, their bound, and daily backups that fail), `LOG` (the two logs), `SET` (the
desktop shell's settings file), `WIN` (the window: its screens, address rules, settings, size and place,
closing), `TRAY` (the tray icon, status line and menu, Quit, the one-time notice), `CLI` (one running
copy and the command line), `AWAY` (when the sim is in use, and staying out of the pilot's way), `OS`
(Windows sign-out and shutdown), `FIRST` (finding a logbook run from source to offer), `NOTE`
(notifications, their clicks and registrations), `UPD` (updates, the quiet-moment install among them),
`TEST` (the unit-test harness).

`[x]` implemented · `[ ]` intended, not yet implemented · `[D]` deferred

## Processes

- [x] **DESK-SHELL-SRV-001**: The desktop shell shall run the bundled server in an Electron utility process, capturing the server's output and error streams through a pipe and holding the utility process's own message channel as the private channel, which no web page or other program can reach.
- [x] **DESK-SHELL-SRV-002**: If an uncaught exception or unhandled rejection occurs in the desktop shell's process, then the desktop shell shall write the error to `desktop.log`, show no Electron error box, and keep running.
- [ ] **DESK-SHELL-SRV-003**: When the desktop shell's process ends, however it ends, a crash included, the server's utility process shall end with it, so no server keeps tracking without the desktop shell.
- [ ] **DESK-SHELL-SRV-040**: If the desktop shell's process crashes outright, then the app shall stay ended, with no watchdog or Windows restart starting it again, until the pilot, MSFS or Windows sign-in next starts it, the tracker's last checkpoint holding the leg.

## Starting the Server

- [x] **DESK-SHELL-SRV-004**: When Electron is ready in the copy holding the single-instance lock (never a start that hands its command line over, nor one with `--quit` or `--unregister`), the desktop shell shall start the server — outside test mode (`--test-data=<folder>`) as soon as its look for a copy run from source has ended (at most 500 ms, DESK-SHELL-FIRST-001), in test mode at once — passing it, at this and every later server start, as start-up arguments (app-shell, APP-SRV-006) the data folder, the program folder (the built page and the seed airport lists), the port, the backups folder, the sim (the sim link or the fake feed), whether airport downloads are on (airports' monthly refresh of the airport lists and any download at start, APT-DATA-020), the logbook to offer (DESK-SHELL-FIRST-004) and, on the starts DESK-SHELL-SRV-044 names, the fresh-run argument (the tracker to start with casual mode off, LIVE-CASUAL-015), with 127.0.0.1 as its address and no version among them (the version is built into the server bundle, DESK-DIST-PKG-009).
- [x] **DESK-SHELL-SRV-005**: While the app runs outside test mode (`--test-data=<folder>`), the desktop shell shall give the server `%LOCALAPPDATA%\MSFS Career Map` as the data folder, the installed program's resources as the program folder, `MSFS Career Map\Backups` under Windows' Documents known folder as the backups folder (looked up by the server at each backup, DESK-SHELL-SRV-008), port 3380, the sim link as the sim (`--sim=link`, LIVE-LINK-012), and airport downloads on (the monthly refresh of the airport lists, and a download at start of a list an import needs that the data folder still lacks after seeding, APT-DATA-020).
- [x] **DESK-SHELL-SRV-006**: While the app runs in test mode (`--test-data=<folder>`), the desktop shell shall give the server `<folder>\data` as the data folder, the packaged program's resources as the program folder — the desktop build output when unpackaged (`npm run desktop`; `build/desktop/`, the folder DESK-DIST-PKG-022 and DESK-DIST-DEV-001 name, never Vite's `dist/`) — `<folder>\Backups` as the backups folder, as a literal path, port 3280, the fake feed (`--sim=fake`; `POST /api/tracker/sample`, LIVE-LINK-003) as the sim, and airport downloads off (neither the monthly refresh of the airport lists nor any download at start, APT-DATA-020, so the lists the test folder was seeded with are never replaced).
- [x] **DESK-SHELL-SRV-041**: The desktop shell shall keep the installed app's data folder (`%LOCALAPPDATA%\MSFS Career Map`), Electron's own folder (`%APPDATA%\MSFS Career Map`) and port (3380) the same in every release (desktop-design › Names and folders: the logbook, the single-instance lock, the settings and the page's remembered choices, kept per origin, are found by them).
- [x] **DESK-SHELL-SRV-007**: If the port the desktop shell gives the server (3380, or 3280 in test mode (`--test-data=<folder>`)) is taken, then the desktop shell shall never fall back to another port, handling it as a held port (DESK-SHELL-SRV-028).
- [x] **DESK-SHELL-SRV-008**: When the desktop shell starts the server outside test mode (`--test-data=<folder>`), it shall give the backups folder as an argument naming Windows' Documents known folder and the path `MSFS Career Map\Backups` under it, for the server to look up at each backup (app-shell's `--backups-documents`, APP-BAK-006), never as a path fixed at the server's start, so a Documents folder moved while the app runs is followed and the lookup is an input the server is given, not a default of its own (in test mode the backups argument is a literal path, DESK-SHELL-SRV-006).
- [x] **DESK-SHELL-SRV-009**: When the desktop shell starts the server, it shall write to `desktop.log` the data folder and the backups folder, outside test mode (`--test-data=<folder>`) as Windows' Documents known folder resolves at that moment.
- [x] **DESK-SHELL-SRV-010**: When the desktop shell starts the server, it shall give it Windows' environment — the path, the user's folders, the temp folder — less `PORT`, `CAREER_DB`, `TRACKER`, `TRACKER_FAKE`, `SIMCONNECT_HOST`, `SIMCONNECT_PORT`, `NODE_OPTIONS` and `ELECTRON_RUN_AS_NODE` (the variables that set a copy run from source's behaviour, APP-SRV-007, LIVE-LINK-002, LIVE-LINK-013, and Node's and Electron's runtime switches), so the installed server links to the sim because its start-up arguments say so (`--sim=link`; the bundled server reads none of them for its inputs, APP-SRV-006, LIVE-LINK-012) and never because of anything left in the environment.
- [x] **DESK-SHELL-SRV-011**: The desktop shell shall start the server with the data folder as its working folder, so the sim link reads a `SimConnect.cfg` only when one is placed there on purpose, never one in the folder the app was started from.
- [x] **DESK-SHELL-SRV-044**: When the desktop shell starts the server and no server it started in this run of the app has yet done its start-up work (DESK-SHELL-SRV-015), it shall pass the server, among its start-up arguments, the fresh-run argument telling the tracker to start with casual mode off whatever its checkpoint holds (app-shell's `--fresh-run`, APP-SRV-011; live-tracking, LIVE-CASUAL-015), and shall leave that argument out of every later server start in the run — a restart after a failure (DESK-SHELL-SRV-024, DESK-SHELL-SRV-027), a requested restart (DESK-SHELL-SRV-043), a start after an update that went no further (DESK-SHELL-QUIT-009) — so casual mode ends with every run of the app however the last run ended, a Windows session end or a crash of the desktop shell included, and survives the server restarts within a run.

## Ready

- [x] **DESK-SHELL-SRV-012**: The desktop shell shall count the server as ready only when `http://127.0.0.1:<port>/api/status` answers naming this app and the process id of the utility process this desktop shell started (`app` and `pid`, APP-API-004).
- [x] **DESK-SHELL-SRV-013**: When the desktop shell starts the server, it shall ask `/api/status` every 250 ms from the start until the server's start-up work is done (DESK-SHELL-SRV-015), bounding by 60 s only the wait for the first ready answer (DESK-SHELL-SRV-012) and never the start-up work after it, and counting no slow or missed answer to these asks after readiness as a failure, leaving that judgement to the 30 s checks for a server that stops answering (DESK-SHELL-SRV-026, DESK-SHELL-SRV-027).
- [x] **DESK-SHELL-SRV-014**: If any other answer comes from the port during the readiness wait — another server of this app among them, whatever its version — then the desktop shell shall treat the port as held (DESK-SHELL-SRV-028) and never count that answer as readiness.
- [x] **DESK-SHELL-SRV-015**: The desktop shell shall count the server's start-up work as done only when the ready server's `/api/status` says outright that it is done (app-shell: `startup` `done`, APP-API-004), never from a status that names no start-up step — opening, backing up, upgrading or bringing in the logbook — the server answering 503 on its API routes other than `/api/status` until then (APP-SRV-009).

## Talking to the Server

- [x] **DESK-SHELL-SRV-016**: When the server's start-up work is done (DESK-SHELL-SRV-015) — at the first start, after every server restart and after **Try again** — the desktop shell shall read `GET /api/tracker` and subscribe to the tracker's event stream `/api/tracker/events`.
- [x] **DESK-SHELL-SRV-042**: If the desktop shell's subscription to the event stream `/api/tracker/events` ends while its server's process runs and the desktop shell is not quitting (DESK-SHELL-QUIT-001), then it shall read `GET /api/tracker` and subscribe again 2 s after the stream ended, waiting twice as long after each attempt that fails, up to 30 s, and keep the tray on the last tracker status received until a subscription succeeds.
- [x] **DESK-SHELL-SRV-017**: The desktop shell shall learn what the tracker is doing only from `GET /api/tracker` and the event stream `/api/tracker/events`, as the page does, and shall never open the logbook database itself.
- [x] **DESK-SHELL-SRV-018**: The desktop shell shall send the server, over the private channel (the utility process's own message channel, which only the desktop shell holds), only these requests (app-shell's messages, APP-SRV-022, each answer repeating the request's id): Back up (`backup`), naming its kind — the daily backup (DESK-SHELL-BAK-001), the backup before an update with the version about to install, or the backup at the installer's or uninstaller's `--quit` (DESK-SHELL-BAK-005) — answered with progress reports (`backup-progress`) while the server copies and then done (`backup-done`, naming the backup file) or failed (`backup-failed`, with a short and a full reason, APP-BAK-008) (APP-BAK-001); Save the tracker's state (`save`), answered done (`saved`) once the state is written (APP-SRV-019); and Shut down (`shutdown`), answered by the server's process exiting (APP-SRV-016).

## Shutting the Server Down

- [x] **DESK-SHELL-SRV-019**: When the desktop shell shuts the server down — on Quit, `--quit`, **Restart to update**, a quiet-moment install (DESK-SHELL-UPD-028) or the end of the Windows session (the session watcher's `session-end`) — it shall send Shut down over the private channel (the utility process's own message channel, which only the desktop shell holds) to any server process that exists, ready or not, whatever point of its start it has reached, and wait up to 10 s for that process to exit (twice the 5 s the server allows itself, APP-SRV-016).
- [x] **DESK-SHELL-SRV-020**: If the server's process is still running 10 s after Shut down, then the desktop shell shall end it, leaving the tracker's last checkpoint to hold the leg.
- [x] **DESK-SHELL-SRV-045**: The desktop shell shall send the server Shut down over the private channel (the utility process's own message channel, which only the desktop shell holds) only when the app is set to quit — Quit, `--quit`, an update about to install, a Windows session end — and never as a way to restart a server (Shut down being the server's sign that the app is quitting, at which it switches casual mode off, live-tracking, LIVE-CASUAL-013; app-shell, APP-SRV-016).

## Quitting

- [x] **DESK-SHELL-QUIT-001**: When Quit goes ahead (with no leg airborne, or once confirmed), `--quit` is handed over, **Restart to update** is clicked, a quiet-moment install begins (DESK-SHELL-UPD-028), or the Windows session ends (the session watcher's `session-end`), the desktop shell shall enter one quitting state, which lasts until the app exits unless a **Restart to update** or a quiet-moment install goes no further (DESK-SHELL-QUIT-009).
- [ ] **DESK-SHELL-QUIT-002**: When the desktop shell enters the quitting state (DESK-SHELL-QUIT-001), it shall close every open message box as if cancelled — Quit's confirmation and the page's confirm dialogs among them — and cancel any update check or download under way.
- [x] **DESK-SHELL-QUIT-003**: While the desktop shell is in the quitting state (DESK-SHELL-QUIT-001), it shall ignore every tray item but **Open MSFS Career Map** and **Show log** — **Restart to update** and **Try again** among them — and a later Quit or `--quit`, except during a **Restart to update** or a quiet-moment install, when it holds them (DESK-SHELL-QUIT-011).
- [x] **DESK-SHELL-QUIT-004**: While the desktop shell is in the quitting state (DESK-SHELL-QUIT-001), it shall start no server — cancelling a scheduled restart, leaving a server that exits ended, and stopping the checks for a server that stops answering and the daily-backup check — and shall stop the update timers.
- [x] **DESK-SHELL-QUIT-005**: When the Windows session ends (the session watcher's `session-end`), whichever quit was already under way, the desktop shell shall abandon any backup still running, wait for no start-list change, send the server Shut down at once, and install nothing.
- [x] **DESK-SHELL-QUIT-006**: When a start with no switch other than `--test-data=<folder>`, a notification click (taken as a start with no switch), or a start with `--background` or `--updated` is handed over while a Quit is under way, up to the desktop shell's last look for such starts just before it exits or hands over to the installer, the desktop shell shall install nothing and, once the app has exited, start the app again with the command line, of those handed over, that shows the most — no switch, then `--updated`, then `--background`.
- [ ] **DESK-SHELL-QUIT-007**: When a start with no switch other than `--test-data=<folder>`, a notification click (taken as a start with no switch), or a start with `--background` or `--updated` is handed over while a **Restart to update** is under way, the desktop shell shall hold it, acting on it if the restart goes no further and dropping it otherwise, since the installer starts the app again.
- [x] **DESK-SHELL-QUIT-008**: When a start with no switch other than `--test-data=<folder>`, a notification click (taken as a start with no switch), or a start with `--background` or `--updated` is handed over while a `--quit` or a Windows session end is under way, the desktop shell shall write it to `desktop.log` and drop it.
- [ ] **DESK-SHELL-QUIT-009**: If a **Restart to update** or a quiet-moment install (DESK-SHELL-UPD-028) goes no further — its backup failed or ran out of time, the sim came into use (DESK-SHELL-AWAY-001: this copy's sim link connected, another copy connected to the sim, or MSFS — `FlightSimulator2024.exe` or `FlightSimulator.exe` — running for this Windows account), a quiet moment's condition stopped holding (DESK-SHELL-UPD-029), or the installer could not be started — then the desktop shell shall leave the quitting state and take up where it was: the tray shows its status line again; the update timers, the daily-backup check and the checks for a server that stops answering run again; every tray item and `--quit` are acted on again, after what was held (DESK-SHELL-QUIT-011: a held `--quit` is acted on and a held Quit dropped, since `--quit` already quits; a Quit held alone asks afresh about a leg in the air, DESK-SHELL-TRAY-021); a window showing the quitting screen goes on as on opening (DESK-SHELL-WIN-032); and, unless the desktop shell had given up on the server (DESK-SHELL-QUIT-010), a server not running — one that exited by itself meanwhile, one whose scheduled restart entering the state cancelled, or one shut down for an install that went no further (DESK-SHELL-UPD-019, DESK-SHELL-UPD-029) — is started again with a fresh count of failures at start (DESK-SHELL-SRV-023).
- [ ] **DESK-SHELL-QUIT-010**: When a **Restart to update** or a quiet-moment install (DESK-SHELL-UPD-028) that went no further leaves the quitting state, the installer not started included (DESK-SHELL-UPD-019), a server the desktop shell had given up on (DESK-SHELL-SRV-035) shall stay given up on, **Try again** still offered.
- [ ] **DESK-SHELL-QUIT-011**: When the pilot chooses Quit, or `--quit` is handed over, while a **Restart to update** or a quiet-moment install (DESK-SHELL-UPD-028) is under way, the desktop shell shall hold it, and, if the update goes no further, act on what it holds once the app has left the quitting state (DESK-SHELL-QUIT-009) — a held `--quit` is acted on and a held Quit dropped, since `--quit` already quits; a Quit held alone asks afresh about a leg in the air (DESK-SHELL-TRAY-021) — and, if the update goes ahead, drop what it holds, a held Quit then leaving the app stopped after a quiet-moment install rather than started again (the install-under-way mark asking for no start, DESK-SHELL-UPD-031).
- [x] **DESK-SHELL-QUIT-012**: While the desktop shell is in the quitting state (DESK-SHELL-QUIT-001) for any quit but a Windows session end, it shall let a start-list change already under way — turning Start with MSFS 2024 or Start with Windows on or off (DESK-START-MSFS-007, DESK-START-MSFS-008, DESK-START-WINDOWS-006, DESK-START-WINDOWS-008) — finish, within that change's own bounds (at most three changed reads, DESK-START-MSFS-040, and 3 s of rename retries, DESK-START-MSFS-041), before it shuts the server down, writing that change's outcome to `desktop.log` and opening no message box for it (entering the quitting state having closed every message box, DESK-SHELL-QUIT-002).

## Backups

- [x] **DESK-SHELL-BAK-001**: The desktop shell shall ask the server for a daily backup when its settings keep no time of a last daily backup, or when more than 24 hours have passed since the time they keep, reckoning those 24 hours from that recorded time and checking once the server's start-up work is done (DESK-SHELL-SRV-015) and every hour after, a daily backup that has failed being asked for again only as DESK-SHELL-BAK-004 says.
- [x] **DESK-SHELL-BAK-002**: If the time of the last daily backup kept in the desktop shell's settings is later than the present, then the desktop shell shall count the daily backup as due.
- [x] **DESK-SHELL-BAK-003**: When a daily backup is done, the desktop shell shall keep its time in its settings as the time of the last daily backup, and clear the count of daily backups failed in a row (DESK-SHELL-BAK-004) together with the record that the backups-failing notification has shown (DESK-SHELL-NOTE-019), so a later run of failures notifies again.
- [x] **DESK-SHELL-BAK-004**: If a daily backup fails, then the desktop shell shall write that to `desktop.log`, count it in its settings among the daily backups failed in a row with the time of the attempt, and ask for it again at the next hourly check after the first failure in a row, and only once 24 hours have passed since the last attempt after any later one.
- [ ] **DESK-SHELL-BAK-005**: The desktop shell shall ask the server for a backup into the backups folder it gave the server before an update installs (DESK-SHELL-UPD-015), its Back up request marked as before an update and naming the version about to install (so the server, when the backups folder cannot be written, can take it into the data folder named by that version, app-shell, APP-BAK-009), and when the installer or uninstaller closes the app with `--quit` (DESK-SHELL-CLI-008), its Back up request marked as at `--quit`.
- [x] **DESK-SHELL-BAK-006**: The desktop shell shall bound each backup it asks for by 60 s without progress — from the request, or from the server's last progress report on the private channel (app-shell's `backup-progress`, APP-BAK-001) — whatever the server is doing, and count a backup that fails or reports no progress for 60 s as failed, leaving what follows to the caller (the update, `--quit`).
- [x] **DESK-SHELL-BAK-007**: When the desktop shell asks for a backup while the server is still starting, ready or not, it shall send the request to that server (app-shell: a server takes a backup asked for during its start-up work once that work is done, APP-BAK-005), inside the same bound (DESK-SHELL-BAK-006).
- [x] **DESK-SHELL-BAK-008**: While the server is waiting out a restart delay or has been given up on (DESK-SHELL-SRV-035), the desktop shell shall count it as no server and ask for no backup.

## Keeping the Server Running

- [x] **DESK-SHELL-SRV-021**: The desktop shell shall treat every exit of the server's process that it did not ask for as a failure, at start or later, but an exit with the code that asks to be started again (DESK-SHELL-SRV-043).
- [x] **DESK-SHELL-SRV-022**: The desktop shell shall count as a failure at start the server's process exiting within 60 s of being started or before its start-up work is done (DESK-SHELL-SRV-015), however long that work took, or not becoming ready (DESK-SHELL-SRV-012) within 60 s of being started, ending the process in that case.
- [x] **DESK-SHELL-SRV-023**: If the server fails at start (DESK-SHELL-SRV-022), then the desktop shell shall start it again 1 s after the first failure at start in a row and 5 s after the second, and give up on it (DESK-SHELL-SRV-035) after the third in a row.
- [x] **DESK-SHELL-SRV-024**: When a server that has run past its first 60 s with its start-up work done (DESK-SHELL-SRV-015) exits without being asked to, other than with the code that asks to be started again (DESK-SHELL-SRV-043), the desktop shell shall start the server again after 1 s with the count of failures at start cleared, however often that happens.
- [x] **DESK-SHELL-SRV-043**: When the server's process exits with the code that asks to be started again (app-shell: code 12, finishing bringing in a logbook, APP-IMP-003) while the desktop shell is not quitting (DESK-SHELL-QUIT-001), the desktop shell shall start the server again at once, counting no failure and clearing the count of failures at start, and, once the new server's start-up work is done (DESK-SHELL-SRV-015), have an open window load the page again as on opening (DESK-SHELL-WIN-001) and ask the new server again for a daily backup the exiting server had not finished, inside a fresh bound (DESK-SHELL-BAK-006), counting the one cut short neither as failed nor among the daily backups failed in a row (DESK-SHELL-BAK-004).
- [x] **DESK-SHELL-SRV-025**: The desktop shell shall never end a server that still answers `/api/status` for taking long over its start-up work.
- [x] **DESK-SHELL-SRV-026**: While a server the desktop shell started runs past its readiness (DESK-SHELL-SRV-012), its start-up work included, the desktop shell shall ask `/api/status` every 30 s, allowing 10 s for each answer.
- [x] **DESK-SHELL-SRV-027**: If three of these 30 s checks of `/api/status` (DESK-SHELL-SRV-026) in a row go unanswered, with nothing received on the event stream in that time once it is subscribed — its keep-alive comments counting, read from the raw stream — then the desktop shell shall end the server with the reason "The server stopped responding" and start it again, counting the failure by DESK-SHELL-SRV-022 to DESK-SHELL-SRV-024, so a hang during start-up work is a failure at start.
- [x] **DESK-SHELL-SRV-028**: When the server exits with the code for its port being in use (code 10, APP-SRV-013), or another server answers during the readiness wait, the desktop shell shall end its own server if it is still running and ask the port's `/api/status` who holds it, naming in each held-port reason, as `<port>`, the port the server was given.
- [x] **DESK-SHELL-SRV-029**: If the held port's holder is this app's server on the same data folder, of any version (one left behind by a desktop shell that ended suddenly), then the desktop shell shall wait up to 20 s for it to end and, if it has not, end the process id it reported only when that process runs the desktop shell's own program file, treating a process id running anything else as another program holding the port (DESK-SHELL-SRV-032).
- [x] **DESK-SHELL-SRV-030**: When the held port's holder is this app's server on the same data folder, and DESK-SHELL-SRV-029 has not found the process id it reported running another program, the desktop shell shall count the attempt as a failure at start (DESK-SHELL-SRV-022) whether or not the leftover was ended, start the next attempt after the usual delay (DESK-SHELL-SRV-023) following the 20 s wait, and, giving up after the third, give the reason "An earlier MSFS Career Map server is still running: quit MSFS Career Map, end any MSFS Career Map still listed in Task Manager, and start it again".
- [x] **DESK-SHELL-SRV-031**: If the held port's holder is this app's server on another data folder, then the desktop shell shall give up on the server at once with the reason "Port <port> is in use by MSFS Career Map in another Windows account, a test copy or a copy run from source".
- [x] **DESK-SHELL-SRV-032**: If the held port's holder is another program answering over HTTP, then the desktop shell shall give up on the server at once with the reason "Port <port> is in use by another program".
- [x] **DESK-SHELL-SRV-033**: If nothing that answers over HTTP holds the port, then the desktop shell shall count a failure at start (DESK-SHELL-SRV-022) like any other and retry, giving up after the third with the reason "Port <port> is in use by another program".
- [x] **DESK-SHELL-SRV-034**: If the server exits with the code for Windows refusing it the port (code 11, APP-SRV-013), then the desktop shell shall give up on the server at once with the reason "Windows reserves port <port> (an excluded port range); restarting Windows may free it" and write Windows' excluded port ranges to `desktop.log`.
- [x] **DESK-SHELL-SRV-035**: When the desktop shell gives up on the server — after the third failure at start (DESK-SHELL-SRV-022) in a row, or at once for a held or refused port (DESK-SHELL-SRV-031, DESK-SHELL-SRV-032, DESK-SHELL-SRV-034) — it shall start no server again until **Try again**, taking as the reason the first that applies: the desktop shell's own reason for the last failure (a held or refused port, a leftover server, "The server stopped responding"); else the last error line the server wrote; else "The server did not start within 60 s" (as when each of the three failures at start was a server not ready within 60 s that wrote no error line).
- [x] **DESK-SHELL-SRV-036**: When the pilot chooses **Try again** in the tray menu (offered only while the desktop shell has given up on the server, DESK-SHELL-TRAY-019) while the desktop shell is not quitting (DESK-SHELL-QUIT-003), the desktop shell shall start the server with a fresh count of failures at start.

## Sleep and the Clock

- [x] **DESK-SHELL-SRV-037**: The desktop shell shall measure every wait and interval of its own on a monotonic clock — the readiness wait and its 250 ms asks, the 60 s that make an exit a failure at start, the restart delays, the 30 s checks for a server that stops answering and the 10 s allowed for each answer, the 20 s wait for a leftover server, the 10 s shutdown wait, the backup bound of 60 s without progress, the hourly daily-backup check, the waits before subscribing to the event stream again, the 2 s allowed for Quit's read of the tracker, the 10 s look at the process list, the update check 1 minute after start and every 4 hours, the 5 minutes a quiet moment must last, the hour a quiet moment waits after a failed backup before an update, the 500 ms look for a copy run from source, and the 5 minutes that count renderer losses — so a change to the system clock moves none of them, reckoning only the 24 hours that span runs, before a daily backup is due and before a failing one is asked for again, from times kept in its settings (DESK-SHELL-BAK-001, DESK-SHELL-BAK-004).
- [x] **DESK-SHELL-SRV-038**: When the PC suspends, the desktop shell shall send the server Save the tracker's state (APP-SRV-019) over the private channel (the utility process's own message channel, which only the desktop shell holds).
- [ ] **DESK-SHELL-SRV-039**: When the PC resumes from sleep, the desktop shell shall start any readiness wait and the count of unanswered `/api/status` checks again from zero, subscribe to the event stream again at once if it ended, and, outside test mode (`--test-data=<folder>`), run the update check if one fell due.
